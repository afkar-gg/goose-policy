Privacy Policy

Last updated: November 9, 2026

Overview

This Privacy Policy explains how Goose collects, uses, stores, and shares data when the bot is used in Discord servers or direct messages. Goose collects only the minimum data needed to provide bot features, moderation tools, AI chat replies, debugging, and server configuration. Goose strictly respects user privacy and complies with Discord's Developer Terms of Service and Developer Policy, including mandatory disclosures for Discord Privileged Gateway Intents: Message Content Intent, Server Members Intent, and Presence Intent.

Privileged Gateway Intents

Goose operates under Discord's Privileged Gateway Intents framework. In accordance with Discord Developer Policies, Goose provides the following disclosures regarding Message Content Intent, Server Members Intent, and Presence Intent:

1. Message Content Intent

Goose requires the Message Content Intent for its primary conversational features:

  • AI Chat Processing: Reading user messages, mentions, and reply chains to generate conversational responses via third-party inference providers (Groq, Cerebras, and Hugging Face).
  • Command Detection: Parsing configured message prefixes (default: s.) and slash commands.
  • Autorespond Triggers: Evaluating incoming messages against server-configured trigger phrases.
  • Attachment Text Analysis: Inspecting attached code or text files (.txt, .js, .lua) for code review and contextual assistance.

Strict In-Memory Processing & Off-Platform Guarantee: All message content is processed strictly in-memory in volatile runtime buffers during active command or AI inference handling. Message content is never stored off-platform (outside of Discord), is never written to persistent databases or disks, and is discarded immediately once the response is delivered.

Zero AI Model Training Guarantee: User messages, prompts, attachments, and server content are sent to third-party inference providers exclusively for transient inference. We explicitly guarantee that messages are never used to train machine learning or AI models.

2. Server Members Intent

Goose uses the Server Members Intent exclusively for the Member Facts feature. When server members ask questions about a user's roles or permissions (e.g., "what roles does @user have?" or "does @user have admin?"), Goose queries guild member data to resolve member information and provide accurate context.

  • On-Demand Role & Permission Lookups: Resolves member roles, permission levels (administrator, manage guild, manage messages, ban, kick, timeout), display names, and nicknames on-demand.
  • Ephemeral In-Memory Caching: Member facts are fetched on-demand and cached in volatile memory for at most 120 seconds to avoid Discord API rate limits during active conversation. They are ephemeral and are never stored off-platform.

3. Presence Intent

Goose uses the Presence Intent for a community management dashboard feature that displays online member status to server administrators and members.

  • Real-Time Member Status Dashboard: Aggregates live online, idle, dnd, and offline availability along with current activity indicators (e.g., game or application status) to assist community organizers in scheduling events and monitoring community engagement.
  • Non-Persistent & Real-Time: Presence data is processed strictly in real-time in volatile memory to render the live dashboard. Goose does not store user activity or presence status off-platform outside of Discord.
  • User Presence Opt-Out via Bot Command: Users have complete control over their presence visibility. You can opt out of having your presence data tracked or displayed on the dashboard at any time by running the bot command s.presence optout or slash command /presence optout. Users can re-enable tracking at any time using s.presence optin or /presence optin.

Data Collected

Depending on enabled features and user actions, Goose may process or store:

  • Account & Guild Identifiers: Discord user IDs, usernames, display names, server IDs, channel IDs, message IDs, role IDs, and permission flags.
  • Message Content & Context: Messages, prompts, replies, command inputs, message links, reply chain context, and recent channel messages needed to generate AI responses. Message content is processed strictly in-memory and is never stored off-platform (outside of Discord).
  • Guild Member & Role Facts: Member role assignments, key server permissions (administrator, manage guild, manage messages, ban, kick, timeout), display names, and nicknames fetched on-demand for the Member Facts feature and not persisted off-platform.
  • Presence & Activity Status: Real-time member availability status (online, idle, dnd, offline) and active game/app indicators processed in-memory for the community dashboard, without off-platform persistence.
  • Submitted Attachments: Attachments submitted for AI features, including supported text files (.txt, .js, .lua), still images, sticker metadata, and image OCR or captions.
  • Server Configuration: Persistent server settings such as command prefixes (default: s.), log channels, ban channels, tempban entries, command settings, autoresponse triggers, ignored user or role IDs, knowledge lines, blacklists, and whitelists.
  • AI Debug & Operational Logs: Diagnostic operational logs, rate limit tracking, and transient AI debug logs (when explicitly enabled by a server administrator) to troubleshoot failures, provider rate limits, and bot availability.

How Data Is Used

Goose uses collected data to:

  • Respond to commands, mentions, replies, direct messages, and configured autoresponse triggers.
  • Run moderation actions and post moderation logs to configured channels.
  • Provide real-time AI conversational replies and Member Facts lookups using in-memory context.
  • Render the real-time online member status dashboard for server administrators and community members.
  • Apply rate limits, blacklists, whitelists, command restrictions, and safety checks.
  • Debug failures, prevent abuse, maintain service reliability, and improve bot behavior.

Goose does not sell personal data, and user messages are never used to train machine learning or AI models.

Third Parties

Goose runs on Discord and uses Discord APIs to receive events and perform bot actions. For AI features, relevant prompts, message context, attachment-derived text, image descriptions, and metadata may be sent over encrypted HTTPS to configured AI providers such as Groq, Cerebras, or Hugging Face.

Data sent to AI providers is strictly for immediate inference generation. None of your message content or prompts are used by Goose or its AI providers to train artificial intelligence or machine learning models.

When users ask for live executor status or web information, Goose may request data from public web pages, WEAO, or URLs included in the user's message. Those third-party services process data under their own policies and operational practices.

Public Content

Goose does not publish user-submitted scripts or files as public raw hosting links. Server moderation logs can still be visible to people who can view the configured log channel.

Do not submit secrets, tokens, private keys, credentials, or highly sensitive personal data to Goose commands or AI prompts.

Retention

Goose enforces granular data retention rules that distinctly separate temporary ephemeral data, persistent server configurations, and moderation records:

Data Category Retention Period Storage Location Description
Ephemeral & In-Memory Data Transient (seconds to 120s max) Volatile RAM only; never stored off-platform Message content, reply chains, AI prompts, Member Facts cache (up to 120 seconds), and real-time presence indicators. Discarded immediately after processing.
Server Configuration Until modified, reset, or bot removed Local bot configuration storage Custom command prefix (e.g. s.), log channel IDs, ban channel IDs, tempban records, autoresponse triggers, ignored roles/channels, and per-server AI quotas.
Moderation & Operational Logs Audit duration / operational need Configured log channels & local log store Moderation actions (bans, kicks, timeouts, reasons, moderator IDs) and temporary operational/error logs needed for rate limit tracking and security abuse prevention.

1. Ephemeral In-Memory Data

Message content, prompts, attachments, and reply chain context are processed strictly in-memory and are never persisted off-platform outside of Discord. Member Facts queries are cached in volatile memory for at most 120 seconds and are never written to disk. Presence tracking data is evaluated in real-time and discarded immediately.

2. Persistent Server Configuration

Server configuration data—including custom server prefixes, designated log channels, ban channels, tempban schedules, autoresponse trigger definitions, knowledge lines, channel permissions, and blacklist/whitelist settings—is retained in configuration storage until explicitly modified, cleared by server administrators, or when Goose is removed from the server.

3. Moderation Records & Operational Logs

Moderation log entries (including user IDs, moderator IDs, actions, and reasons) are sent directly to the server's configured log channel. Active tempban records remain until the ban expires or is cleared. Operational logs required for diagnosing system errors, provider rate limits, and abuse prevention are periodically rotated and removed.

Choices & Opt-Outs

Users and server administrators have several controls over their data and bot interactions:

  • Presence Tracking Opt-Out: Any user can opt out of presence and activity status tracking across servers where Goose operates by executing the bot command s.presence optout or slash command /presence optout. Once opted out, the user's online and activity status is immediately excluded from the community dashboard. To resume presence tracking, users can run s.presence optin or /presence optin.
  • Server Administration: Server administrators can remove Goose from a server at any time, reset configurations, change command prefixes, configure ignored channels or roles, and enable or disable moderation logging and autoresponses.
  • Message Content Privacy: Users can choose not to interact with Goose commands or mention the bot, and can avoid posting sensitive personal information or credentials in Discord channels where Goose is present.

Security

Goose uses access controls, Discord permissions, and operational safeguards to limit unauthorized access. No system can be guaranteed completely secure, so users should not send secrets or highly sensitive information to the bot.
